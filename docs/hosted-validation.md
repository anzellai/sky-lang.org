# Official release validation and read-only deployment checks

The automatic website workflow runs on the rollout branch, pull requests and main. It downloads Sky0.29.8 from the official release and verifies the published checksum before executing it. It uses Ubuntu24.04, Go1.26 and locked Playwright1.58.2 with Chromium and WebKit. It never deploys.

The two original test suites and the original eleven admin refusal assertions remain unchanged. Tests use a throwaway PostgreSQL service and synthetic settings. Dotenv paths are removed without opening them. No production settings or credentials are supplied. The Home-only source change is retained. No optional blog post is added.

The existing production recipe remains `sky build --target web:app src/Main.sky`, followed by the existing static Linux backend Go build. The native backend, paired frontend, SDK loaders, compressed files, content and fallback pages are archived together. The artifact facts bind the full tracked source excluding dotenv, exact source commit, official compiler bytes and every archive member. The browser job verifies the same artifact before and after running it. It does not rebuild the application. The application's normal scratch startup performs migrations and seeds source posts only in that job's temporary database.

The browser checks require an actual Wasm load, hydration, both new capability captions, blog and post navigation in the same document, source-post links, four viewport widths and zero page errors. Unknown requests and mutating RPCs fail. Only the resolved read-only init and published-post loading RPCs are allowed. The source authority hashes cover every application module and the unchanged admin refusal script. Archive falsifiers and pure request policy tests run in CI. Both browsers must also pass a loopback redirect fixture with zero requests reaching the other server.

The production-smoke workflow is manual. Run it only after an authorised artifact installation succeeds. Give it the exact deployed commit. It selects a successful exact-source automatic CI producer and downloads that run's paired artifact. It performs no build, database setup, seed, deployment, form submission or provider action. Public HTTP checks require exact source/version, SSR, health, SDK/Wasm/compressed equality, security headers, protected console and the original eleven safe admin refusals. Browser checks use the same source-bound read-only route policy. Service workers are blocked. Context-level routing fetches with zero redirects and rejects3xx before browser fulfilment. HTTP probes also do not follow redirects. No authentication cookie or production credential is supplied.

The full artifact is suitable for the existing artifact-only installation after official release and parent review. Keep the existing server configuration, content/database, Live fallback and previous binary. Do not use this workflow as permission to initialise or reseed a production database. There is no automatic installation or production smoke on push or pull request.
